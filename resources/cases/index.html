Troque o contexto. Veja a experiência mudar.

Os cases não descrevem apenas o que poderia ser adaptado. Cada página permite alterar sinais simulados disponíveis ao browser/aplicação e observar, em tempo real, a política e a interface resultantes.

Regra: adaptar às condições observadas, não fabricar identidade. Cada simulador mostra sinal → contexto → decisão → experiência.

Como os cinco se combinam

1. InteraçãoComo a interface pode ser operada agora.
2. RecursosQuanto é razoável baixar, processar e animar.
3. ApresentaçãoComo a UI deve respeitar preferências explícitas.
4. Região & tempoComo formatar e contextualizar sem assumir identidade.
5. ComposiçãoComo sinais simultâneos viram uma policy única.

Arquitetura de decisão

ObservedContext
      ↓
NormalizedContext { value, source, timestamp }
      ↓
DerivedContext { only when needed, confidence, evidence, ttl }
      ↓
Policy Engine { purpose, precedence, constraints, override }
      ↓
Adaptation { layout, interaction, presentation, content context, resources }
      ↓
New observation → reevaluate
